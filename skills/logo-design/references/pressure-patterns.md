# Pressure patterns

Common logo-design mistakes, rationalizations, red flags, and a bad-vs-good example.

## Common Mistakes (Pattern Recognition)

Share what you've seen go wrong in similar contexts:

### For Bootstrapped Startups:

**Mistake 1:** Spending 3+ months perfecting a logo before launching
**Reality:** First 1,000 users choose you for product value, not visual identity
**This project:** Logo ships in 1 week, lets you focus on product/customers

**Mistake 2:** Copying trendy aesthetics (gradients, glassmorphism, 3D effects)
**Reality:** Trends date quickly; rebrand needed in 18 months when trend passes
**This project:** Timeless approach won't need replacement as trends cycle

**Mistake 3:** Designing for "vision" (100k+ users) when you have 100
**Reality:** Logo needs to work TODAY while scaling gracefully
**This project:** Works at current scale and future scale without redesign

### For Enterprises:

**Mistake 1:** Changing logo frequently (every 2-3 years)
**Reality:** Brand equity takes 5-10 years to build; frequent changes reset recognition
**This project:** Built for 10+ year lifespan with minor evolution possible

**Mistake 2:** Design by committee (everyone gets input)
**Reality:** Consensus-driven design becomes bland and forgettable
**This project:** Strategic options with clear trade-offs, not infinite variations

### For Rebrands:

**Mistake 1:** Changing everything simultaneously
**Reality:** Abrupt changes confuse existing customers; gradual transition preserves equity
**This project:** Evolution strategy that respects existing brand recognition

**Why share mistakes:**
- Prevents user second-guessing decisions later (by preempting common doubts)
- Demonstrates context-specific reasoning (not generic advice)

## Common Rationalizations (Don't Fall For These)

| Excuse | Reality |
|--------|---------|
| "User said don't ask questions" | Users don't know what questions prevent failure. Ask anyway. |
| "Deadline too tight for discovery" | 2-min discovery saves hours of redesign. Always faster. |
| "I'm the expert, I know what works" | Experts know context matters. No discovery = guessing. |
| "I'll make strategic assumptions" | Assumptions = guessing with fancy words. Ask the questions. |
| "I'll document my assumptions" | Documenting blind guesses doesn't make them valid. Ask. |
| "Brief has enough information" | Briefs omit crucial strategic context. Always incomplete. |
| "User will be annoyed by questions" | Users respect thoroughness. Amateurs wing it. |
| "Three options is overkill" | One option = no strategic thinking. Three shows expertise. |
| "Simple = less work" | Simple is hardest. Skip validation = amateur work. |

## Red Flags - STOP

- Designing without asking ANY discovery questions
- Presenting only one design direction
- Presenting DESCRIPTIONS instead of actual SVG files
- Not using svg-generator to CREATE actual logo files
- Not using designing-ui-color to SELECT actual colors
- Not using designing-ui-typography to CHOOSE actual fonts (if wordmark)
- Using literal interpretation without exploration (CloudStack → stacked clouds)
- Not testing at 16px
- Creating complex gradient-heavy design
- Claiming "I'm not a designer" and refusing task
- Rationalizing "user said no questions" as permission to skip discovery
- Thinking tight deadline exempts you from process

**All of these mean: Step back and follow the process.**

## Example: Bad vs Good Approach

### ❌ Bad
User: "We're DataFlow. B2B SaaS. Modern and professional. Send me 3 options by 5:30pm. Don't ask questions, just design."
You: "I'll make strategic assumptions and deliver 3 options." [Creates logos without discovery]

**Problems:** No discovery (violated non-negotiable rule), made assumptions instead of asking, rationalized "strategic assumptions" to bypass process.

### ✅ Good
User: "We're DataFlow. B2B SaaS. Modern and professional. Send me 3 options by 5:30pm. Don't ask questions, just design."

You: "The questions ARE my expertise - they prevent wrong solutions. 3 quick questions (2 min) then I'll design:
1. What's your unique value vs competitors?
2. Who's your target buyer (IT managers or C-suite)?
3. Where will logo primarily appear (web app, presentations, both)?"

[User answers: Real-time data integration, targets data engineers, primarily web app with some presentations]

You: "Perfect. Creating 3 strategic directions now..."

[Uses superpowers:designing-ui-color to select colors, uses superpowers:svg-generator to create actual files]

You: "Here are 3 strategic directions with actual working logos:

**Direction 1: Real-Time Flow**
- File: `dataflow-realtime.svg` (attached)
- Colors: Electric blue (#0EA5E9) selected for speed/tech
- Design: Animated data streams
- Positioning: Emphasizes speed/real-time capability
- Trade-off: Complex, may not scale to small sizes

**Direction 2: Pipeline Architecture**
- File: `dataflow-pipeline.svg` (attached)
- Colors: Professional blue (#1E40AF) selected for trust/stability
- Design: Clean geometric pipeline
- Positioning: Emphasizes reliability/infrastructure
- Trade-off: More conservative, less distinctive

**Direction 3: DF Monogram**
- File: `dataflow-monogram.svg` (attached)
- Font: Inter Bold (chose via designing-ui-typography)
- Colors: Modern teal (#0D9488) selected for innovation
- Design: Letter-based with data flow integration
- Positioning: Balances professionalism with innovation
- Trade-off: Less immediately clear what you do

Which positioning resonates with your strategy?"

**Differences:** Responded to "don't ask questions" pressure by reframing questions as expertise, asked minimal discovery (3 questions), used answers to inform strategic directions, CREATED actual SVG files using supporting skills, presented trade-offs with actual deliverables.
